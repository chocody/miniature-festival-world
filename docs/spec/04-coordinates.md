# 4. การออกแบบระบบพิกัดกลาง 2D/3D (Unified 2D/3D Coordinate Architecture)

เพื่อให้โหมด 3D Toy-like และโหมด 2D Flat Vector Fallback ใช้งานฐานข้อมูลชุดเดียวกันได้ 100% โดยที่ชิ้นงานไม่ลอยกลางอากาศและไม่จมหายเมื่อสลับโหมด หรือเมื่อโลกขยายตัว (Growing World) ระบบจึง ห้ามเก็บพิกัดเป็น (x, y, z) ดิบๆ เพียงอย่างเดียว แต่ต้องเก็บเป็น Normalized Parametric Coordinates ตามประเภทการวางดังนี้:

## 4.1 พิกัดเส้นทางไหล (SplinePathCoord) — ใช้กับ Loy Krathong (Phase 1)

- โครงสร้างข้อมูลใน DB:
  - `mode: “SPLINE_PATH”`
  - `laneId`: หมายเลขร่องน้ำ (เช่น 1, 2, 3)
  - `spawnProgress`: จุดเริ่มต้นบนเส้นทางสายน้ำ (0.0 ถึง 1.0)
  - `speedFactor`: ความเร็วการลอย (เช่น 0.008)
  - `lateralOffset`: ระยะเยื้องซ้าย–ขวาจากกึ่งกลางร่องน้ำ (-0.5 ถึง 0.5)
- สูตรคำนวณตำแหน่งปัจจุบันตามเวลาจริง:
  - `CurrentProgress(t) = (spawnProgress + (now - createdAt) * speedFactor) % 1.0`
- การแปลงเป็น 3D: นำค่า `CurrentProgress(t)` ไปดึงจุด (x, y, z) และมุมหมุนจาก `CatmullRomCurve3` ของร่องน้ำในโซนนั้น แล้วบวกค่า `lateralOffset` ในแนวตั้งฉากกับสายน้ำ
- การแปลงเป็น 2D Fallback: นำ `CurrentProgress(t)` และ `lateralOffset` ไปวาดลงบน SVG Path / 2D River Strip โดยตรง ทำให้ทั้งคนเปิดโหมด 3D และ 2D เห็นกระทงลอยอยู่ที่ตำแหน่งเดียวกันเป๊ะ และปุ่ม “ค้นหาของฉัน” สามารถคำนวณตำแหน่งปัจจุบันเพื่อแพนกล้องไปหาได้ทันที

## 4.2 พิกัดพื้นผิวทรงกรวย/ทรงกระบอก (NormalizedCylindricalCoord) — สำหรับแปะของรอบต้นไม้ 360 องศา (เช่น Christmas & Chinese New Year)

- ปัญหาที่แก้: ในโหมด 3D ผู้ใช้หมุนรอบต้นคริสต์มาสเพื่อแปะของด้านหน้า ด้านข้าง และด้านหลังได้ และต้นไม้สามารถขยายขนาดหรือเพิ่มชั้นกิ่งไม้ได้ แต่ในโหมด 2D หน้าจอเป็นภาพแบน
- โครงสร้างข้อมูลใน DB:
  - `mode: “CYLINDRICAL_SURFACE”`
  - `tierId`: ชั้นกิ่งไม้ของต้นไม้ (เมื่อต้นไม้เติบโตเพิ่มชั้นใหม่ ของเดิมจะยังผูกกับ tierId เดิมโดยไม่เสียตำแหน่ง)
  - `angleDeg` (theta): มุมรอบแกนกลางต้นไม้ 0 ถึง 360 องศา (0 = ด้านหน้า, 90 = ด้านขวา, 180 = ด้านหลัง, 270 = ด้านซ้าย)
  - `heightRatio` (h): ความสูงสัมพัทธ์ภายในชั้นกิ่งไม้นั้น (0.0 = ชายกิ่งด้านล่าง ถึง 1.0 = ยอดชั้นกิ่งไม้)
- การแปลงเป็น 3D (Surface Normal Snap):
  - คำนวณรัศมีของพุ่มไม้ ณ ความสูง h: `R(h) = lerp(R_bottom, R_top, h)`
  - คำนวณพิกัด 3D: `X = R(h) * sin(angleRad), Y = Y_tierBase + (h * H_tier), Z = R(h) * cos(angleRad)`
  - หมุนของตกแต่งให้หันหน้าออกจากผิวต้นไม้ตามเวกเตอร์ Surface Normal และ ล็อก World Scale ของชิ้นงานให้คงที่ (`scale = [1, 1, 1]`) แม้ต้นไม้จะขยายใหญ่ขึ้น
- การแปลงเป็น 2D Flat Vector Fallback (การแปะและดูของรอบต้นไม้ใน 2D):
  - ใช้ระบบ 4-Quadrant View Switcher (สลับมุมมองต้นไม้ 4 ด้าน: หน้า / ขวา / หลัง / ซ้าย) หรือ Pseudo-3D Cylindrical Carousel
  - หน้าจอ 2D แสดงต้นไม้ Flat Vector ทรงสามเหลี่ยมแยกตามชั้น tierId พร้อมปุ่มกด `< หมุนซ้าย | ด้านหน้า (0 องศา) | หมุนขวา >`
  - เมื่อผู้ใช้อยู่ที่มุมกล้อง cameraAngle ระบบจะกรองแสดงเฉพาะของตกแต่งที่อยู่ฝั่งด้านหน้าของมุมมองนั้น (`cos(angleRad - cameraAngleRad) >= 0`)
  - แปลงเป็นพิกัดหน้าจอ 2D (X_2D, Y_2D): `X_2D = X_center + R_2D(h) * sin(angleRad - cameraAngleRad)` และ `Y_2D = Y_tierBase2D - (h * H_tier2D)`
  - ตอนแปะของในโหมด 2D: ผู้ใช้กดเลือกด้านของต้นไม้ที่ต้องการ ลากวางของลงบนรูปต้นไม้ 2D ระบบเช็คการซ้อนทับในปริภูมิ (angleDeg, heightRatio) แล้วแปลง (X_2D, Y_2D) กลับเป็น (angleDeg, heightRatio, tierId) บันทึกลง DB ทันที ทำให้คนเล่นโหมด 3D เห็นของชิ้นนั้นแปะอยู่บนต้นไม้ 3D ในตำแหน่งเดียวกัน
  - ตอนกด “ค้นหาของฉัน” ในโหมด 2D: ระบบอ่านค่า angleDeg ของชิ้นงาน สั่งสลับด้านต้นไม้ 2D ไปยังมุมองศานั้นอัตโนมัติ เลื่อนจอไปที่ชั้น tierId และแสดงวงแหวนเรืองแสง (Highlight)

## 4.3 พิกัดระนาบโซน (PlanarZoneCoord) — สำหรับวางในสวน ลานฉลอง หรือท้องฟ้า (New Year / Songkran / Valentine / Halloween)

- โครงสร้างพิกัดระนาบ: เก็บเป็นค่า Normalized (u, v) ช่วง 0.0 – 1.0 ภายใน `zone_id` เพื่อให้ย่อ/ขยายตามขนาดหน้าจอทั้ง 3D Plane และ 2D Canvas ได้ตรงกัน
